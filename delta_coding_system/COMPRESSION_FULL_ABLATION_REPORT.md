## 1. 实验目标

这次重测的目标有两个:

1. 用统一指标重新测一遍所有已探索方案
2. 做完整组件消融，回答每个组件到底贡献了什么

这次统一记录了以下指标:

### 1.1 参考差值解释能量

设目标激活为 $x$，参考激活为 $r$。

$$
E(x) = \|x\|_2^2
$$

$$
\text{RawRefEnergyExplained} = 1 - \frac{\|x-r\|_2^2}{\|x\|_2^2}
$$

这个量可以为负。若为负，表示“直接拿参考做差”反而比不用参考更差。

### 1.2 仿射变换解释能量

当前系统使用的仿射参考为:

$$
\hat{x}_{\text{aff}} = \alpha r + \beta
$$

$$
\text{AffineEnergyExplained} = 1 - \frac{\|x-(\alpha r + \beta)\|_2^2}{\|x\|_2^2}
$$

### 1.3 仿射增益

$$
\text{AffineGain} = \text{AffineEnergyExplained} - \text{RawRefEnergyExplained}
$$

这个量专门衡量“仿射变换本身”的边际贡献。

### 1.4 重建解释能量与残差编码损失

若最终重建为 $\hat{x}$，则:

$$
\text{ReconEnergyExplained} = 1 - \frac{\|x-\hat{x}\|_2^2}{\|x\|_2^2}
$$

$$
\text{ResidualCodingLoss} = 1 - \text{ReconEnergyExplained}
$$

这比之前脚本中的 `quantization_loss` 更准确，因为这里度量的是“残差编码后仍然损失多少目标能量”。

### 4.2 组件实际贡献

按 `prev` 路径拆分:

1. **原始前一 token 参考本身几乎没法直接用**

   - `ablate_prev_raw_ref` 的 ReconE = **-2.2852**
   - 这表示直接拿前一 token 当重建，不只是“不够好”，而是比零基线还差很多

2. **仿射变换本身提供了第一步修复**

   - `ablate_prev_affine_only` 的 ReconE = **0.0340**
   - 仿射相对 raw reference 的边际收益:

   $$
   0.033952 - (-2.285245) = 2.319197
   $$

   也就是说，prev-token 路径能成立，首先靠的是仿射把一个很差的参考拉回到可编码状态。

3. **真正决定效果的是残差编码，而不是参考本身**

   - `ablate_prev_affine_int4_k0`: ReconE = **0.992453**
   - 从 affine-only 到 Int4 k0 的提升:

   $$
   0.992453 - 0.033952 = 0.958501
   $$

   也就是说，这条路径的主要恢复能力来自“发送残差”，不是来自参考自身解释力。

4. **top-k outlier 有效，但增益已经很小**

   - top-1 相对 k0 增益: **+0.000654**
   - top-2 相对 top-1 增益: **+0.000481**

   所以 `prev_int4_k2` 的合理性在于: 它用很小的额外字节换回了稳定的尾部质量。

### 4.3 Unigram 路径结论

1. prev-reference 本身不是强解释器
2. affine 是必要组件
3. 残差编码是决定性组件
4. `prev_int4_k2` 仍是默认推荐点
5. `prev_gs256_k2` 是最有潜力的 metadata 压缩变体

### 5.2 组件实际贡献

1. **参考本身已经很强**

   - `ablate_delta_raw_ref` ReconE = **0.764355**
   - 说明 trigram/bigram reference 已经解释了 76.4% 的目标能量

2. **仿射有价值，但不是决定性**

   - `ablate_delta_affine_only` ReconE = **0.828156**
   - affine 边际收益:

   $$
   0.828156 - 0.764355 = 0.063801
   $$

3. **残差编码把最后一段误差补齐**

   - `ablate_delta_affine_int4_k0` ReconE = **0.996607**
   - 从 affine-only 到 Int4 k0 的提升:

   $$
   0.996607 - 0.828156 = 0.168451
   $$

4. **top-1 outlier 有效但很小**

   - baseline 相对 k0 增益:

   $$
   0.998210 - 0.996607 = 0.001603
   $$

### 5.3 Delta 路径结论

1. Delta 路径的主要优势来自高质量 reference
2. affine 只是在已经很强的 reference 上再抬一小截
3. 显式稀疏传输整体不划算
4. Delta 路径若要继续压缩，最现实的方向还是 Int2，而不是各种稀疏花样

## 6. 关键对比与推荐

### 6.1 默认推荐

**`prev_int4_k2`**

- 全局压缩率: **3.4536×**
- 全局平均余弦: **0.9811**
- unigram 字节: **2964 B**
- unigram ReconE: **0.993588**

推荐原因:

1. 质量稳定
2. 压缩显著优于 baseline
3. 组件行为最清楚
4. 工程复杂度最低

### 6.2 激进推荐

**`prev_gs256_k2`**

- 全局压缩率: **3.6214×**
- 全局平均余弦: **0.9807**
- unigram 字节: **2764 B**
- unigram ReconE: **0.992434**

它是当前最值得继续验证的下一步，因为它不是靠激进稀疏，而是靠减少 metadata。

### 6.3 不推荐方向

1. `unigram_int4_k4 / k8`
2. 显式 group/channel 级稀疏 delta
3. 2:8 结构稀疏 delta
4. 把更复杂的小模型参考作为主方向

## 7. 最终结论

### 7.1 关于 prev-token 路径

最终结论不是“前一 token 本身很像当前 token”，而是:

1. 前一 token 原始参考本身很差
2. affine 能把它修正到可编码状态
3. 真正恢复高质量的是后续残差编码

所以 prev-token 方案的本质是:

**用一个弱但可仿射修正的参考，配合便宜的低比特残差编码，替代昂贵的 Int8 原始发送。**

### 7.2 关于 delta 路径

最终结论是:

1. trigram/bigram reference 本身已经解释了大部分能量
2. affine 只是额外小修
3. 再往下压时，稀疏收益有限
4. Int2 是唯一仍有现实意义的激进方向

### 7.3 后续实验固定记录项

以后所有实验建议固定记录这 7 个指标:

1. `raw_ref_cosine`
2. `raw_ref_energy_explained`
3. `affine_ref_cosine`
4. `affine_energy_explained`
5. `affine_gain`
6. `recon_energy_explained`
7. `residual_coding_loss`

这 7 个量足够把“参考作用”“仿射作用”“残差编码作用”完全拆开。
